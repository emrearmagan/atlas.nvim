1. INTRODUCTION                              *atlas* *atlas.nvim* *atlas-introduction*

Review pull requests and manage issues across GitHub, GitLab, Bitbucket,
Azure DevOps and Jira without leaving your editor.

==============================================================================
2. INSTALLATION                                            *atlas-installation*

With lazy.nvim:
>lua
  {
    "emrearmagan/atlas.nvim",
    dependencies = {
      "nvim-tree/nvim-web-devicons",              -- optional, recommended
      "esmuellert/codediff.nvim",                  -- optional, PR diffs
      "sindrets/diffview.nvim", -- optional; or "dlyongemallo/diffview-plus.nvim"
    },
    -- See |atlas-configuration|.
    opts = {},
  }
<
With vim.pack (Neovim 0.12+):
>lua
  vim.pack.add({
    "https://github.com/emrearmagan/atlas.nvim",
  })

  -- See |atlas-configuration|.
  require("atlas").setup({})
<

------------------------------------------------------------------------------
REQUIREMENTS                                               *atlas-requirements*

  - Neovim 0.10+
  - `git` and `curl` 7.83+ on `$PATH`
  - For GitHub: the `gh` CLI, authenticated via `gh auth login`
  - For Bitbucket: Bitbucket Cloud API token (`api.bitbucket.org`)
  - For GitLab: GitLab 17.7+ and a Personal Access Token with the `api` scope
  - For Azure DevOps: Personal Access Token (`dev.azure.com`)
  - For Jira: Cloud REST API v3 or Server REST API v2

CodeDiff requires v3.0.0 or newer. Diffview and Diffview-plus are also supported.
These viewers can display Atlas comment, task, and note overlays, but their
integrations rely on plugin internals and may break after upstream changes.

Run `:checkhealth atlas` after configuring providers to see what's wired
up and what's missing.

>lua
  require("atlas").setup({
    ui = {
      statusline = {
        -- false keeps your existing statusline. A function(buf, win, context)
        -- decides per window; `context` is "atlas" for dashboards/details and
        -- "diff" for diff views.
        enable = true,
        -- For example, keep your statusline in Atlas detail views:
        -- enable = function(buf, win, context)
        --   return vim.bo[buf].filetype ~= "atlas-ui.detail"
        -- end,
      },
      -- "auto", "default", "snacks", or "fzf-lua".
      picker = "auto",
      -- Make the main Atlas dashboard a listed buffer.
      listed_buffer = false,
    },

    providers = {
      ---@type AtlasBitbucketConfig
      bitbucket = {
        user = vim.env.BITBUCKET_USER,
        token = vim.env.BITBUCKET_TOKEN,
        cache_ttl = 300, -- Set to 0 to disable caching.
      },
      ---@type AtlasGitHubConfig
      github = {
        -- hostname = "github.company.com", -- Defaults to GH_HOST, then github.com.
        cache_ttl = 300, -- Set to 0 to disable caching.
      },
      ---@type AtlasGitLabConfig
      gitlab = {

        -- Personal Access Token with `api` scope:
        -- https://docs.gitlab.com/ee/user/profile/personal_access_tokens.html

CUSTOM ACTIONS                                    *atlas-custom-actions*
                       *atlas-pulls-custom-actions* *atlas-issues-custom-actions*

Add project-specific actions to pull requests and issues. Custom actions
receive the current item and provider context, making it possible to call
local scripts, open repositories in tmux, copy branch names, or connect Atlas
to your own tooling. They appear in the action menu (default `A`).

>lua
  pulls = {
    repo_config = {
      paths = {
        ["your-workspace/*"] = "~/code/repos/*",
      },
      settings = {},
    },
    custom_actions = {
      {
        id = "show_repo_status",
        label = "Show repository status",
        icon = "",
        confirm = "Show repository status?",
        ---@param pr PullRequest
        ---@param ctx AtlasPullsCustomActionContext
        ---@param done fun(ok: boolean|nil, message: string|nil)
        run = function(_, ctx, done)
          if not ctx.repo_path then
            done(false, "No repo path")
            return
          end

          local function write(_, data)
            if data then ctx.write(data) end
          end
          vim.system({ "git", "status", "--short" }, {
            cwd = ctx.repo_path,
            stdout = write,
            stderr = write,
          }, function(result)
            if result.code ~= 0 then
              done(false, "Failed to read repository status")
              return
            end
            done(true, "Repository status loaded")
          end)
        end,
      },
    },
  },
  issues = {
    custom_actions = {
      {
        id = "copy_branch_name",
        label = "Copy branch name",
        icon = "",
        ---@param issue Issue
        ---@param ctx AtlasIssuesCustomActionContext
        ---@param done fun(ok: boolean|nil, message: string|nil)
        run = function(issue, ctx, done)
          local branch = string.format("%s/%s", issue.key, issue.title:lower():gsub("%s+", "-"))
          vim.fn.setreg("+", branch)
          done(true, "Copied: " .. branch)
        end,
      },
    },
  }
<

Use `ctx.write(text)` to show output and `done(ok, message)` to finish the action.
>lua
  ctx.write("Running checks...\n")
  done(true, "Checks passed")
<

4. COMMANDS                                                    *atlas-commands*

                                                                      *:Atlas*
:Atlas
        Pick an Atlas command.

:Atlas pulls [provider|.]
:Atlas issues [provider|.]
        Open a provider dashboard. Without an argument, it opens the only
        configured provider or asks you to choose. `.` uses the current
        repository's provider.

:Atlas review [pull-request-url|number|.]
        Pick an open or draft pull request in the current repository and open
        its diff. With a URL or a number (`12`, `#12`, or GitLab `!12`), open
        that pull request directly. `.` opens the current branch's pull
        request.

:Atlas diff <base...head>
        Open a Git range with the configured diff viewer
        (`pulls.diff.open_cmd`).

:Atlas pipelines [target|.]
        Open pipelines by branch name, PR URL or number (`123`, `#123`, or
        GitLab `!123`), or a GitHub Actions, GitLab pipeline, or Bitbucket
        Pipelines build URL. Branch names use the local repository;
        `.` uses the current branch.

:Atlas notes [target|.]
        Open the notes manager, optionally filtered to a pull request. `.`
        shows the notes of the current repository's pull requests.

:Atlas create pr
        Create a pull request from the current branch.

:Atlas create issue [provider|.]
        Create an issue. Without a provider, it uses the only one that can
        create issues or asks you to choose. `.` uses the current repository's
        provider.

:Atlas search [provider|.]
        Search configured pull-request and issue providers. `.` uses the
        current repository's provider.

:Atlas open [target|.]
        Open a pull request or issue by provider URL, Jira key, or PR/issue
        number (`123`, `#123`, or GitLab `!123`) in the current Git
        repository. `.` opens the current branch's pull request. Without a
        target, it prompts for one.

:Atlas browse [repository URL|.|page] [page]
        Open the repository browser. Use `.` for the current repository.
        With only a page name, pick a repository first. A URL to a
        repository page or item, such as `/issues` or `/pull/3`, opens
        that page.
        Examples: `:Atlas browse . branches`, `:Atlas browse issues`

:Atlas clear [cache|notes|reviewed|stars]
        Clear all Atlas data, or only cached data and cloned repositories,
        notes, locally saved reviewed file marks, or locally starred items.

:Atlas logs
        Toggle the Atlas log buffer.

:Atlas console
        Open the latest command output.

5. PULLS                                                          *atlas-pulls*

Use `:Atlas pulls [provider|.]` to browse and manage pull requests from
GitHub, Bitbucket, GitLab, and Azure DevOps. Shared authentication and
endpoints are configured in |atlas-configuration|.

PULLS CONFIGURATION                              *atlas-pulls-configuration*

>lua
  require("atlas").setup({
    pulls = {
      delete_notes = false, -- delete notes after approval, merge, or decline
      default_merge_method = "merge", -- "merge" or "squash"
      default_delete_source_branch = false,
      git_transport = "https", -- "https" or "ssh" for Atlas-managed Git remotes.
      description = {
        include_summary = true,
        include_commit_hashes = true,
        include_related = true,
        include_diffstat = false,
      },
      -- Replaces the built-in Conventional Comments templates.
      comment_templates = {
        insert_mode = true, -- enter Insert mode after applying a template
        items = {
          { label = "Suggestion", text = "suggestion: " },
          { label = "Issue", text = "issue: " },
          { label = "Nitpick", text = "nitpick: " },
        },
      },
      diff = {
        -- "auto", or a command that accepts explicit <base>...<head> Git revisions.
        open_cmd = "auto", -- CodeDiff, DiffviewOpen or AtlasDiff
        comment_display = "virtual_lines", -- or compact "virtual_text" hints
        review_panel = {
          hidden = true, -- set false to show the review panel initially
          height = 10,
        },

        -- AtlasDiff options; external viewers use their own configuration.
        layout = "inline", -- "inline" or "side-by-side"
        compact = true, -- initially show hunks plus surrounding context
        lsp = {
          enabled = false, -- real files for LSP (AtlasDiff and CodeDiff)
          dir = nil,       -- absolute path or fun(ctx): string|nil; see below
          link = {},       -- e.g. { "node_modules", ".venv" }
        },
        explorer = {
          grouped = true, -- group changed files by directory
          hidden = false,
          show_commits = false, -- set true to show commits below changed files initially
          width = 40,
          initial_focus = "explorer", -- "explorer" or "diff"
          preview = false, -- show a file when the explorer cursor moves onto it
          focus_on_select = false, -- move into the diff after selecting a file
          ignore = { ".git/**", ".jj/**" },
        },
      },
      repo_config = {
        -- Map `namespace/repo` -> local path for checkout / diffs / actions.
        -- PR checkout prefers the matching checkout or worktree Atlas is run
        -- from, then falls back to these paths.
        -- Diffs of other repositories use a clone in the cache, removed after
        -- 30 days without a review.
        paths = {
          ["your-workspace/*"]    = "~/code/repos/*",
          ["your-workspace/atlas"] = "~/code/atlas",
          ["group/subgroup/*"]    = "~/code/subgroup/*",
        },
        settings = {
          ["your-workspace/atlas"] = {
            -- Optional file paths; these are the default values.
            readme        = "README.md",
            pr_template   = ".github/pull_request_template.md",
            merge_method  = "squash", -- overrides default_merge_method
            delete_source_branch = true, -- overrides default_delete_source_branch
          },
        },
      },
      custom_actions = {}, -- see |atlas-pulls-custom-actions|
    },
  })
<

NOTES                                                          *atlas-notes*

Notes let you leave something on a diff without posting it to the pull request.
Each note is attached to a file and line and can be an ISSUE, SUGGESTION, NOTE,
or PRAISE.

For scripts, use `bin/atlas-notes`. Notes added there appear in AtlasDiff,
CodeDiff, Diffview, Diffview-plus, and `:Atlas notes`:
>sh
  ./bin/atlas-notes add \
    --target https://github.com/owner/repository/pull/123 \
    --commit 3f2a9c1e \
    --file lua/review_queue.lua --start-line 19 \
    --type suggestion --body "Should this be a bool?"
<

LSP FOR REVIEWS                                            *atlas-pulls-lsp*

Set `pulls.diff.lsp.enabled = true` to use your configured language servers for
hover and go-to-definition on the new side of AtlasDiff or CodeDiff. This is off
by default.

The diff uses a detached worktree at the head revision, removed when the diff
closes. The default directory is
`stdpath("cache")/atlas/worktrees/<repo>/pr-<id>`, or
`stdpath("cache")/atlas/worktrees/<repo>/<sha>` without a pull request.

Set `pulls.diff.lsp.dir` to an absolute path, or a function receiving
`{ repo_root, repo_full_name, pr_id, head_sha, default }` that returns a path
or nil.

Set `pulls.diff.lsp.link` to dependency folders such as `node_modules` or `.venv`.
They are symlinked from your checkout into the worktree so language servers
can resolve dependencies. These are the same directories on disk, not copies.

PIPELINES                                             *atlas-pulls-pipelines*

View pipelines and their jobs, inspect their status, and read job logs directly
in Atlas. See |atlas-commands| for `:Atlas pipelines` targets.

Pipelines use your provider's CI by default. Set `ci.backend` to use your own.
For Bamboo on Bitbucket, use `require("atlas.pulls.pipelines.bamboo").new(opts)`
with `host`, `user`, and `password`.

>lua
  providers = {
    github = {
      ci = {
        backend = {
          fetch = function(context, opts, done)
            -- Fetch pipelines with their stages and jobs.
            done({}, nil)
          end,
          fetch_job = function(context, pipeline, job, done)
            -- Fetch the updated job, including any steps.
            done(job, nil)
          end,
          fetch_job_log = function(context, pipeline, job, done)
            -- Fetch the job's raw log output.
            done({ raw = "Your log output here" }, nil)
          end,
          parse = function(log)
            -- Return cleaned lines or your own nested groups.
            return log.lines
          end,
          actions = {
            -- Add your actions here.
          },
        },
        highlights = {
          { pattern = "^FAIL%s", level = "error" },
          { pattern = "deprecated", level = "warn", hl_group = "DiagnosticWarn" },
        },
      },
    },
  }
<

`ci.highlights` controls log highlighting using Lua patterns. Set `level` for
a severity color or `hl_group` for an existing Neovim highlight group.

GITHUB PULLS                                              *atlas-pulls-github*

Uses the `gh` CLI. No tokens to configure in the plugin - run
`gh auth login` once. Views accept any GitHub search expression.

>lua
  pulls = {
    ---@type AtlasGitHubPullsConfig
    github = {
      views = {
        { name = "My PRs", key = "1", layout = "plain", -- "compact", "grouped", or "plain"
          -- current_repo = true, -- Limit this view to the local repository.
          search = "author:@me sort:updated-desc" },
        { name = "Team",   key = "2", layout = "compact",
          search = "org:your-org sort:updated-desc" },
        { name = "Repo",   key = "3", layout = "grouped",
          search = "repo:your-org/your-repo" },
      },
      bookmarks = {
        -- key   = "S",      -- default
        -- label = "Search", -- default
        items = {
          ["Drafts"]           = "is:pr is:draft author:@me",
          ["Recently merged"]  = "is:pr is:merged author:@me sort:updated-desc",
          ["Review requested"] = "is:pr is:open review-requested:@me",
        },
      },
    },
  }
<

6. ISSUES                                                        *atlas-issues*

Use `:Atlas issues [provider|.]` to browse and manage Jira, GitHub, GitLab,
and Azure DevOps issues. Shared authentication and endpoints are configured in
|atlas-configuration|.

ISSUES CONFIGURATION                            *atlas-issues-configuration*

Shared config that applies to all issue providers:
>lua
  issues = {
    with_relationships = true, -- fetch parent/subissue relationships
    custom_actions = {}, -- see |atlas-issues-custom-actions|
  }
<

Issue views support "plain" and "compact" layouts. Jira also supports "board",
which groups the current page by workflow status.

------------------------------------------------------------------------------
JIRA                                                       *atlas-issues-jira*

Jira Cloud uses REST API v3 and Jira Server uses REST API v2. Cloud auth
normally uses an email and API token (see
https://support.atlassian.com/atlassian-account/docs/manage-api-tokens-for-your-atlassian-account/
for how to create one). Server instances may use basic or bearer auth. Views
are saved JQL queries.

The Markdown editor for Jira descriptions and comments is experimental. The
overview tab can toggle between Markdown and ADF to inspect the conversion.

>lua
  issues = {
    ---@type AtlasJiraIssuesConfig
    jira = {
      project_config = {
        -- Global story points field. Defaults to "customfield_10016".
        story_points_field = "customfield_10016",
        -- Override issue type styles by name (lowercase).
        issue_types = {
          bug = { icon = "" },
          maintenance = { icon = "", hl_group = "AtlasTextWarning" },
          infrastructure = { icon = "󰒋", hl_group = "AtlasLogInfo" },
        },
        -- Override icons by status name or category.
        status_icons = {
          new = "●",
          indeterminate = "",
          done = "",
          ["In Review"] = "",
        },

        -- Fields and defaults per project; see JIRA PROJECT FIELDS below.
        KAN = { ... },
      },
      views = {
        { name = "My Board",  key = "M", layout = "board",
          jql = "project = KAN AND assignee = currentUser() ORDER BY updated DESC" },
        { name = "Team Board", key = "T", layout = "compact",
          jql = "project = KAN ORDER BY updated DESC" },
      },
      bookmarks = {
        -- key   = "J",   -- default
        -- label = "JQL", -- default
        items = {
          ["Backlog"]     = "project = KAN AND statusCategory != Done AND (sprint IS EMPTY OR sprint NOT IN openSprints()) ORDER BY Rank ASC",
          ["Next sprint"] = "project = KAN AND sprint in futureSprints() ORDER BY Rank ASC",
          ["My open"]     = "assignee = currentUser() AND statusCategory != Done ORDER BY updated DESC",
        },
      },
    },
  }
<

------------------------------------------------------------------------------
JIRA PROJECT FIELDS                                 *atlas-issues-jira-fields*

Custom fields to display go under `fields` in the project's entry, keyed by
Jira field ID. Replace `KAN` with your project key.

>lua
  KAN = {
    fields = {
      customfield_10003 = {
        name = "Approvers", -- the field's label
        format = function(value) -- what the detail panel shows
          if type(value) ~= "table" or #value == 0 then
            return nil -- nil hides the field
          end
          return table.concat(value, ", ")
        end,
        hl_group = "AtlasChipActive",
        display = "chip", -- "chip" or "table"
      },
    },
    -- Pre-fills new issues, with values as Jira shows them.
    defaults = {
      issue_type = "Story",
      fields = {
        priority = "High",
        labels = { "backend" },
        components = { "Backend", "Frontend" },
        customfield_10050 = "Platform",
      },
    },
  }
<

To find out which custom fields your project has, expand the field names of
any issue:

  https://your-site.atlassian.net/rest/api/3/issue/KAN-1?expand=names

`names` maps each field ID to its name, and `fields` holds the value `format`
receives.

If you came here to replace the browser with this plugin, here's a curl for
you:
>sh
  curl -s -u "you@example.com:your_jira_api_token" \
    "https://your-site.atlassian.net/rest/api/3/issue/KAN-1?expand=names" \
    | jq .names
<
Once you have the ID, use `jq .fields.customfield_10003` to see the value
`format` receives.

On Jira Server/Data Center, use `/rest/api/2/`, and with bearer auth
`-H "Authorization: Bearer your_jira_api_token"`.

AZURE DEVOPS WORK ITEMS                                   *atlas-issues-azure*

Uses the shared `providers.azure` authentication from |atlas-configuration|.
Views use flat WIQL queries.
Syntax: https://learn.microsoft.com/en-us/azure/devops/boards/queries/wiql-syntax?view=azure-devops

Azure supports both HTML and Markdown for work-item descriptions and comments.
Pandoc (https://pandoc.org) is needed to view and edit HTML as Markdown.
Saving converted content switches it to Markdown permanently.
Descriptions: https://devblogs.microsoft.com/devops/markdown-support-arrives-for-work-items/
Comments: https://learn.microsoft.com/en-us/rest/api/azure/devops/wit/comments/get-comments?view=azure-devops-rest-7.1#commentformat

>lua
  issues = {
    ---@type AtlasAzureIssuesConfig
    azure = {
      views = {
        {
          name = "Assigned",
          key = "1",
          project = "YourProject",
          -- current_repo = true, -- Use the project of the local repository instead of project.
          search = [[
            SELECT [System.Id] FROM WorkItems
            WHERE [System.TeamProject] = @project AND [System.AssignedTo] = @Me
            ORDER BY [System.ChangedDate] DESC
          ]],
        },
      },
    },
  }
